# RAG Agent 前端设计规格

日期：2026-08-14

## 1. 目标与范围

为现有 RAG Agent 后端增加一套可完整体验现有能力的 Web 前端。产品以 Agent 对话为主入口，并覆盖知识库、文档摄取、会话、引用和服务状态管理。

设计参考 Yuxi 的现代知识库工作台信息层级与聊天体验，但只实现当前后端已经提供的能力，不复制其多租户、知识图谱、Skills、MCP、模型管理或权限系统。

首版成功标准：用户可以通过浏览器完成“创建知识库、上传文档、观察处理进度、创建会话、流式提问、核验引用、管理文档与会话”的完整流程，并能通过 Docker Compose 一键启动前后端。

## 2. 已确认的产品决策

- 交付完整可用版，而非仅包含上传和聊天的演示版。
- 采用聊天优先布局。
- 仅提供浅色模式。
- 使用 Vue 3、TypeScript、Vite 和 Pinia。
- 前端作为独立 Docker Compose 服务运行。
- 浏览器统一请求 `/api/v1`，开发环境由 Vite、容器环境由前端 Web Server 反向代理到 FastAPI，因此不要求后端开放 CORS。
- 默认前端地址为 `http://127.0.0.1:5173`。

## 3. 信息架构与导航

应用使用两级导航：

1. 深色全局侧栏提供新对话、会话、知识库、文档和系统状态入口。
2. 聊天页面增加会话历史栏，中央区域专注于 Agent 对话。

当前知识库是全局上下文。聊天页顶部显示当前知识库并允许切换。若尚未选择知识库，页面引导用户选择或创建知识库，不发送无上下文请求。

桌面端点击回答中的引用标签后，从右侧打开引用详情抽屉；窄屏下使用底部面板。设计不包含深色模式。

## 4. 前端工程结构

前端位于仓库根目录的 `frontend/`：

```text
frontend/
├─ src/
│  ├─ api/          HTTP 接口、下载和 SSE 客户端
│  ├─ components/   通用界面组件
│  ├─ layouts/      应用外壳与聊天布局
│  ├─ pages/        路由页面
│  ├─ router/       Vue Router 配置
│  ├─ stores/       Pinia 状态
│  ├─ styles/       浅色设计系统与响应式规则
│  └─ types/        与后端 Schema 对齐的类型
├─ tests/           单元和组件测试
├─ Dockerfile
└─ package.json
```

`docker-compose.yml` 增加 `frontend` 服务。开发命令使用 Vite 热更新；容器交付使用构建后的静态资源和反向代理配置，支持前端路由刷新回退到 `index.html`。

## 5. 页面设计

### 5.1 聊天首页 `/chat`

- 左侧显示当前知识库的会话历史，并支持创建和切换会话。
- 顶部提供当前知识库选择器。
- 中央显示历史用户消息、助手消息、Agent 状态和检索状态。
- 发送消息后立即乐观显示用户消息，再通过 SSE 读取服务器事件。
- 支持 `message_start`、`agent_status`、`retrieval_start`、`retrieval_result`、`token`、`citation`、`message_end` 和 `error` 事件。
- `token` 事件持续追加到当前助手消息；`citation` 事件加入消息引用；`message_end` 后重新读取持久化消息，使前端状态与数据库一致。
- 回答中的 `[S1]` 等引用标签可打开来源详情。
- 流式失败时保留已经接收的内容并显示重试操作。重试需要用户主动触发，前端不自动重复发送，避免产生重复消息。
- 后端不支持修改会话标题，因此首版不提供重命名。

### 5.2 知识库 `/knowledge-bases`

- 列出、创建、查看、切换和删除知识库。
- 创建表单包含名称、描述、Embedding 模型和向量维度。
- 知识库卡片显示后端实际提供的模型、维度和时间信息。
- 文档数量只能在加载该知识库文档后计算；不得伪造聚合字段。
- 删除前显示确认对话框，并说明相关文档、会话和索引将一并删除。

### 5.3 知识库详情 `/knowledge-bases/:id`

- 展示知识库基本信息和文档列表。
- 支持上传 `.md`、`.txt` 和 `.pdf`，单文件上限 5 MiB。
- Markdown/TXT 使用 `local` 解析器或省略解析器；PDF 允许选择 MinerU 或 PaddleX。
- 上传成功后保存 `task_id` 并轮询摄取任务，显示等待、处理、完成或失败状态及后端提供的进度。
- 支持下载原文、结构化解析结果和解析图片。
- 支持失败任务重试和文档删除。
- 后端没有摄取任务列表接口。页面刷新后以文档状态为准，只有当前浏览器会话中已知的任务显示精细进度。

### 5.4 会话管理 `/conversations`

- 按知识库筛选会话。
- 展示标题、创建时间和更新时间。
- 消息数量需要在进入或加载消息后计算，不将其伪装成后端聚合字段。
- 支持进入对话和删除会话。
- 空状态提供创建第一场对话的入口。

### 5.5 系统状态 `/status`

- 调用 `/api/v1/health/live` 展示 API 存活状态。
- 展示浏览器到前端服务及前端代理到 API 的连接结果。
- 当前后端没有 PostgreSQL、Redis、MinIO、Milvus 等组件的独立健康接口。页面明确标记这些检测项为“后端未提供”，不推断或伪造状态。

### 5.6 文档与引用预览

- Markdown/TXT 原文通过下载接口读取并以安全的纯文本或 Markdown 只读视图呈现。
- PDF 使用浏览器原生预览能力；无法内嵌时提供下载。
- 结构化解析结果以格式化 JSON 或结构视图呈现。
- 文档图片使用现有 `/images/{asset_index}` 接口按已知资源索引加载。
- 引用详情显示文件名、章节、页码、相关度、引用片段、文档 ID 和 chunk ID。

## 6. 状态边界

Pinia Store 按业务边界拆分：

- `knowledgeBaseStore`：知识库列表、当前知识库、创建和删除。
- `conversationStore`：会话列表、当前会话和持久化历史消息。
- `chatStore`：SSE 生命周期、临时消息、Agent 状态、检索事件、引用和失败恢复。
- `documentStore`：文档列表、上传、已知摄取任务、轮询和下载。

页面局部 UI 状态，如抽屉开关、表单输入和临时筛选，不进入全局 Store。

## 7. API 与数据流

HTTP 客户端统一处理基础路径、JSON、错误响应和文件下载。TypeScript 类型与后端 Pydantic Schema 对齐，UUID 在前端使用字符串表示。

聊天主流程：

```text
选择知识库
→ 创建或选择会话
→ 乐观显示用户消息
→ POST SSE 请求
→ 展示 Agent 与检索状态
→ 逐段合并 token
→ 收集并关联 citation
→ message_end
→ 重新加载持久化消息
```

文档摄取主流程：

```text
前端校验文件
→ multipart 上传
→ 保存 document_id 与 task_id
→ 轮询 ingestion task
→ 同步刷新文档状态
→ completed 或 failed 后停止轮询
```

轮询在页面卸载、任务完成或任务失败时停止；网络临时失败使用有上限的退避重试，不能无限制造请求。

## 8. 错误和边界处理

- API 层统一解析后端错误结构；无法解析时使用 HTTP 状态和通用网络错误信息。
- 表单级错误显示在字段附近，操作级错误使用页面通知。
- 网络中断或 SSE 异常不会清空已经显示的消息内容。
- 删除知识库、文档和会话都需要显式确认。
- 上传前校验扩展名、非空文件和 5 MiB 上限。
- 404 知识库或会话显示可恢复空状态，并提供返回列表的操作。
- 真实模型、Reranker 或解析器未配置时，展示后端错误和排查入口，不生成虚假成功结果。
- 下载和预览使用后端返回的 Content-Type；文本渲染需要转义，不执行文档中的脚本或 HTML。

## 9. 视觉与响应式规则

- 仅浅色主题：白色主表面、冷灰背景、深炭色导航、靛蓝主操作色、绿色仅表示成功。
- 字体层级克制，避免大型营销式标题；页面强调内容和任务状态。
- 桌面端保持会话历史与聊天并列；中等宽度可折叠会话历史；移动端全局导航变为可展开菜单。
- 引用抽屉在桌面端从右侧出现，在窄屏下改为底部面板。
- 所有交互控件支持键盘焦点；状态不只依靠颜色表达。

## 10. 测试与验收

### 10.1 自动化测试

- Vitest 测试 API 数据转换、错误解析、Store 状态转换和 SSE 事件归并。
- Vue Test Utils 测试上传表单、任务状态、聊天消息、引用详情和错误状态。
- Playwright 覆盖主链路：创建知识库、上传文档、等待完成、创建会话、发送流式消息、查看引用。
- TypeScript 类型检查和 Vite 生产构建必须通过。

### 10.2 Docker 验收

- `docker compose up -d --build` 能启动 frontend、api、worker 和基础设施。
- `http://127.0.0.1:5173` 可访问。
- 前端 `/api/v1` 代理能访问 FastAPI。
- 直接刷新 `/chat`、`/knowledge-bases/:id` 等前端路由不会返回 404。
- 不要求修改浏览器 CORS 配置。

### 10.3 手工验收

- 新用户能从空状态完成首次知识库创建和文档上传。
- 文档处理进度和失败信息可见。
- Agent 回答按 SSE 渐进显示，并能核验引用来源。
- 页面刷新后会话与消息从后端恢复。
- 删除知识库、文档和会话的结果会同步反映在界面中。

## 11. 明确不在首版范围内

- 登录、注册、多租户和权限管理。
- 知识图谱、MCP、Skills、子 Agent 和沙盒文件系统。
- 模型提供商或密钥配置页面。
- 会话标题修改，因为后端没有对应接口。
- 全基础设施健康详情，因为后端没有对应接口。
- 深色模式。
- 前端伪造后端没有提供的指标、聚合或成功状态。
